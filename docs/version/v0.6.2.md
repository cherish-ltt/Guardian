# v0.6.2

修复字典「默认值」可以同时勾选多项的问题：同一字典类型现在只保留一个默认项，
升级时线上已有的多默认数据会被自动收敛。后端与前端都有改动，版本号同步递增到 `0.6.2`。

## 后端

- **同一字典类型最多一个默认项**：`create_dict_data` / `update_dict_data` 改为在写事务内执行，
  写入前先把同类型其它项的 `is_default` 清 0，再落库。改字典类型时按「更新后的最终状态」收敛，
  把默认项整条搬到另一个已有默认项的字典类型也不会撞约束。
- **迁移 `0009_dict_default_unique.sql`**：升级启动时先把每个字典类型里多余的默认项降级为普通项
  （保留排序最靠前的一项，排序相同按主键），再建部分唯一索引
  `uk_sys_dict_data_default ON sys_dict_data (dict_type) WHERE is_default = 1`。
  迁移是追加式的，不改 `0002` 的建表语句；存量数据无需人工处理，也不需要停服清库。
- **数据库层兜底**：绕过接口直接改库写入第二个默认项会被唯一索引拒绝，不再依赖调用方自觉。

## 前端

- **字典数据表单补约束说明**：「默认值」开关下新增「同类型只保留一个默认项，设置后原默认项自动取消」，
  行为不变，用户能直接看到规则。
- **样本册行内设默认失败时按服务端数据恢复**：此前接口失败只回滚当前行，其它行仍停在
  「已被取消默认」的本地状态；现在重新拉取该字典数据，界面与数据库保持一致。
