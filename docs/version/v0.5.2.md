# v0.5.2

对 `v0.5.0` 与 `v0.5.1` 的后端改动做了一轮复核，修掉两个安全与数据一致性缺陷。
后端有实质改动，前端无改动，版本号按约定同步递增。

## 后端

- **重置口令现在会让旧令牌彻底失效**：`v0.5.0` 里管理员重置他人口令后只删除了会话存储里的
  令牌，没有递增 `auth_version`。如果 Redis 清理失败、或令牌索引本身缺失，旧 JWT 仍然能通过
  验签并继续用到 TTL 到期——而这恰恰是「怀疑账号被盗后重置口令」最需要防住的场景。
  现在口令更新与版本递增在同一事务内完成；缓存清理移到事务外，Redis 故障不会回滚已生效的
  口令重置（与二次验证换恢复码的处理一致）。

  同时新增 `AccountRepository::bump_auth_version`，只更新 `auth_version` 单列。
  原写法读出整行再写回（`save_security` 是整行覆盖），在多处并发写同一用户的
  安全状态时会把别处刚写入的字段覆盖成旧值。

- **自定义数据范围校验部门存在性**：`dataScope=CUSTOM` 时传 `deptIds` 此前不校验这些部门是否
  真实存在，可以往 `sys_role_dept` 写入不存在的部门 ID，留下悬空关联。现在保存角色时在事务内
  校验，不存在的部门返回 `400 部门不存在或已删除`。用户侧的 `roleIds` / `postIds` 在 `v0.5.0`
  已有同类校验，角色侧当时漏了。

- **验证码字模完整性测试**：新增断言，保证字符集里每个字符都有合法的 7×5 点阵。
  字形缺失时渲染会静默跳过该字符，图上看不到、用户必然输错，而原有测试发现不了。

- **文档与注释纠错**：`docs/ADMIN.md` 的 `/auth/captcha` 说明与 `auth_controller` 的文档注释
  仍写着「明文回显给登录页」，与 `v0.5.0` 改成图片验证码后的实际行为不符，已改正。

## 前端

- 无。版本号随本次发布同步递增到 `0.5.2`，代码无改动。

## CI

- **覆盖率步骤不再重复跑测试**：`cargo llvm-cov` 本身就是一次完整的测试执行，此前又单独跑一遍
  `cargo test`，CI 时间翻倍。现在合并为一个步骤。
- **`scripts/check-coverage.py` 错误处理**：报告文件缺失、不是合法 JSON、结构不符合 llvm-cov
  输出时，给出明确的一行报错而不是 Python traceback。退出码行为不变（异常一律非零）。
