# v0.5.0

本次发布按生产级标准补齐了安全、数据一致性与前端稳定性上的缺口，并给 CI 加了覆盖率护栏。
对外行为有若干**不兼容变更**，升级前请先读「不兼容变更」一节。

## 不兼容变更

- `GET /api/v1/auth/captcha` 不再返回 `code` 字段，改为 `image`（`data:image/svg+xml;base64,...`）。
  仍从响应里读明文验证码的第三方脚本必须改为识别图片，或关闭验证码参数。
- `POST /api/v1/system/users/{id}/reset-password` 的 `password` 改为必填，不再有内置默认口令。
- 列表接口的 `pageNum` / `pageSize` 传非法值时返回 `400`，不再静默回落默认值。
  前端已同步；直接调接口的脚本若依赖旧的宽容行为需要修正。
- `/api/v1/examples/*` 只在 debug 构建注册，release 包访问返回 `404`。
- 新增用户未传口令时改用系统参数 `sys.user.initPassword`，参数为空才回退 `SEED_ADMIN_PASSWORD`。

## 后端

- **验证码不再回显明文**：`/auth/captcha` 由服务端生成内联 SVG 图片，明文只留在会话存储里比对；
  随机源从 UUID 片段换成系统随机数。
- **登录防爆破**：密码阶段接入失败计数，连续 5 次错误锁定 5 分钟，锁定期内不再校验口令；
  账号不存在时也付出一次 Argon2 校验成本，避免响应时间泄露账号是否存在。
- **重置口令安全加固**：删除硬编码默认口令 `DEFAULT_RESET_PASSWORD`，新口令必填；
  管理员重置他人口令后撤销该账号全部会话（`auth_version` 递增 + 令牌删除）。
- **内置管理员保护**：`PUT /system/users/{id}` 补上「内置管理员不允许停用」校验，
  与 `/status` 接口保持一致。
- **CUSTOM 数据权限可写**：`RoleWriteCommand` 增加 `deptIds`，角色仓储新增 `sys_role_dept` 的
  读与全量替换；CUSTOM 必须带部门，切回其他范围会清空既有部门范围；删除角色一并清理。
- **关联校验**：新增或编辑用户时在事务内校验 `roleIds` / `postIds` 指向的记录存在，
  失败整体回滚，不再留下悬空关联行。
- **软删与唯一索引**：新增 `0006_partial_unique_indexes.sql`，把用户 / 角色 / 岗位的唯一索引
  重建为 `WHERE deleted = 0` 的部分索引。此前删除后重建同名记录会被数据库拦下并返回 409。
- **分页参数语义统一**：`pageNum` / `pageSize` 与 `status` 等过滤参数一致，非整数或负数返回 400；
  同时移除 `PageQuery` 里从未被仓储使用的 `sortField` / `sortOrder`。
- **示例接口按构建门控**：`/examples/*` 与 `dev-login` / `dev-transfer` 一样只在 debug 注册。
- **`/system/health` 文档对齐**：OpenAPI 去掉不存在的 503 分支（该分支属于 `/system/ready`）。
- **新增用户口令来源统一**：改为先读 `sys.user.initPassword`，参数为空才回退 `SEED_ADMIN_PASSWORD`，
  与 `docs/ADMIN.md` 和前端提示一致。

## 前端

- **会话缓存容错**：`session.user()` 解析失败时清掉缓存并返回 `null`，不再让脏 localStorage
  在模块初始化阶段抛错导致整站白屏。
- **响应解析容错**：`http.parseJson` 对非 JSON 响应（网关 502 HTML 等）返回同形状对象，
  抛出的仍是带真实状态码的 `ApiError`，而不是 `SyntaxError`。
- **用户多角色 / 多岗位**：用户表单的角色与岗位改为多选。后端 `roleName` / `postName` 是逗号
  拼接的多值，原来按名字反查单个 ID 会把多角色用户裁剪成单角色。
- **登录页改用图片验证码**：不再渲染明文，改 `<img>` 展示服务端下发的 SVG。
- **组件引入统一**：61 处 `@/components/ui/Xxx.vue` 直引改为从 `@/components/ui` 引入，
  与 `frontend/AGENTS.md` 的硬性约定一致。
- **新增 lint**：引入 `oxlint`（固定 1.88.0）与 `npm run lint`，CI 与 pre-commit 都接入。
- **README 修正**：目录表改为「登录与两步验证、工作台、个人资料、10 个管理页」，
  补上漏掉的 `scripts/account-regression.mjs`，并补齐第三方依赖的许可说明。

## 文档与配置

- `backend/AGENTS.md`：修正 Clippy 启用位置（是 `src/lib.rs` 的 `#![warn(...)]`，不是
  `Cargo.toml` 的 `[lints.clippy]`）、IPv4 / IPv6 双地名库的现状、版本示例与 CI 的 paths 口径。
- `backend/.env` 补 `IP_LOCATION_V6_DB_PATH`，与 `.env-example` 的键集合一致。
- 根 `README.md` 修正 `docs/TESTING.md` 的错误路径。
- `docs/DEPLOYMENT.md` 补自建 musl 包的正确命令，并说明 `CARGO_TARGET_*_LINKER=musl-gcc`
  会让产物变成 dynamic-pie、启动即段错误。

## CI 与发布

- **musl 链接配置修正**：musl 目标只设 `CC_<target>=musl-gcc`，去掉
  `CARGO_TARGET_<TARGET>_LINKER=musl-gcc`。后者让 rustc 用 `musl-gcc` 当链接器，产物变成
  dynamic-pie，运行到 musl 的 `_start_c` 直接段错误；默认配置下 rustc 用自带的 rust-lld
  产出 static-pie。打包前新增校验：产物不得有 `INTERP` 段与 `NEEDED` 依赖。
- **工具链统一**：`release.yml` 的 Rust 工具链从 `@stable` 改为固定 `1.99.0`，与 `backend.yml` 一致。
- **paths 修正**：`backend.yml` 的 glob 统一成 `backend/**/*.rs` 风格，并补 `backend/vendor/**/*.rs`。
- **覆盖率护栏**：CI 新增 `scripts/check-coverage.py`，全局行覆盖率低于 80% 直接失败。
  此前这条门槛只写在 `AGENTS.md` 与 README 里，没有任何机制拦住回退。
