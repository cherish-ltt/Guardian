# v0.11.0

个人资料页支持查看本人的有效登录会话，经身份复核单独退出旧会话，保留当前和其他可信会话（#34，PR #39）。

## 后端

- 新增本人有效登录会话的游标列表与单项撤销接口，无需菜单权限；撤销要求当前密码及已启用的第二因素，只影响所选的其他会话。
- 会话列表返回非凭据标识与浏览器 / 系统名称，不返回 JWT、Redis key 或 IP；兼容旧 Redis SET 与缺少 `jti` 的 JWT，管理映射沿用原 TTL。
- 复用独立失败计数与一次性证明消费；Redis 故障明确返回 503，删除后的清理失败可用新证明重试确认，不恢复已消费的第二因素。
- 列表清理保留并发新版本及同名新账号会话；全量撤销不再最后删除整个用户索引，避免丢失并发新登录的索引。

## 前端

- 个人资料页新增登录会话面板，展示当前项、登录与到期时间、浏览器 / 系统，支持刷新、游标加载更多和经安全证明单项撤销。
- 沿用现有表格、弹窗及浅深主题，窄屏表格内部滚动；撤销失败保留目标行，慢请求防重复提交，换号后的旧响应不会写回新会话。
- 增加四个独立浏览器上下文回归及桌面 / 移动端截图，验证目标退出后其他会话保持有效。

## 验证

- 后端全量测试 368 passed、5 个外部 Redis 用例默认 ignored，行覆盖率 94.34%（10098/10704）；本次新增的 3 个 Redis 用例在隔离实例中另行执行通过，另 2 个原有缓存 Redis 用例未运行。
- 会话 Router / 故障专项 15 项通过，覆盖归属、过期、2FA 防重放、部分删除失败及并发新会话保护；真实 Redis 覆盖旧索引、原 TTL 和 151 会话分页。
- 前端 46 项单元测试、类型检查 / 构建、lint、适用提交钩子通过；功能 PR 的前后端 CI 均成功。
- 四个独立 Chrome contexts 实测：撤销目标后其受保护请求返回 401，当前、另一个本人会话及另一账号保持有效；500 失败不删行、慢请求防重复及换号旧响应隔离通过。
- 已检查 1440×1080、390×844 的浅色 / 深色截图，页面无横向溢出，窄屏表格内部滚动。仓库截图记录功能验收时的 v0.10.1 构建，不是 v0.11.0 发布包截图。

## 升级说明与限制

- 前后端统一为 v0.11.0，需配套更新；没有新增运行依赖、数据库迁移或必填环境变量。
- 旧会话保持原到期时间，缺失客户端元数据时显示未知；列表代表有效凭据，不代表实时在线，浏览器 / 系统名称可伪造，时间按浏览器本地格式显示。
- 当前会话继续使用已有退出入口；单项撤销不修改密码、2FA 配置或账号安全版本，也不能撤销已执行的业务副作用。
- 每次列表请求只对本人索引执行一轮 `SSCAN COUNT 50`；COUNT 是 Redis 提示，不承诺严格条数上限。管理映射按原 TTL 过期，不延长认证有效期。
- Redis 503 可能发生在目标已删除之后；已消费的第二因素不会恢复，重试须提供新证明。仅验证独立 Redis，跨键 Lua 不承诺 Redis Cluster 兼容。
- 浏览器验证使用 Chrome 引擎；2FA 撤销与 Redis 多页边界由后端回归覆盖，未进行 Firefox / Safari、实体手机或生产部署验收。上游 `proc-macro-error2 2.0.1` 的 Rust future-incompatibility 提示仍存在。
