# v0.12.0

本版本新增首次登录与重置后改密、启动配置预检，以及代码生成配置的结构同步和永久移除；完善跨标签页换号、确认框和迟到响应的会话隔离（#33、#41、#42、#43）。

## 后端

- 新增用户与重置密码支持可选的首次登录改密要求；待改密会话仅可读取本人信息、改密或退出，超管及骨架接口同样受限。成功改密原子清除要求并撤销旧会话，保留迁移兼容、2FA 顺序及 Redis 故障边界。
- 新增 `--check-config`：沿用环境 / `.env` 规则，检查现有配置约束、驱动连接配置解析及已配置 xdb 后退出；
  不连接 SQLite / Redis、迁移 / 播种、创建数据库 / 日志或监听 HTTP，诊断不回显敏感配置原值。
- 代码生成器新增只读结构差异预览与事务同步；保留表身份和未变字段设置，拒绝过期确认，实际改动后置为待人工确认，覆盖整体回滚、并发、权限与审计。
- 保存完整 SQL 声明类型，旧配置以原基础类型回填；同步后的代码预览与 ZIP 使用同一份配置，继续限制单列 `INTEGER` 行号主键。
- 新增单表生成配置移除接口，在事务中删除父子元数据，保留业务表、数据和文件；重导使用新 ID，旧请求不能影响新配置（#42）。

## 前端

- 用户新建和重置弹窗增加默认关闭的改密开关；登录与刷新先核实身份，待改密账号进入独立页面，无需菜单权限；成功后统一重新登录，并隔离重复提交、跨标签页及迟到响应。
- 同一会话重复收到待改密响应时保留正在提交的改密结果，成功后正确清除会话并跳转登录。
- 生成器新增「同步结构」弹窗，展示新增 / 删除以及类型、可空性、主键、顺序的前后差异；支持取消与确认，失败后重新预览，防止旧会话异步响应更新页面。
- 同步结构弹窗按打开时的 token 和会话版本绑定预览与确认；会话变化后停止提交及回调，卸载后忽略迟到响应，避免旧成功提示或列表刷新影响当前页面。
- 代码生成页面增加「移除配置」确认，明确自定义配置永久丢失；成功刷新列表及导入候选，失败保留原行。确认、删除和刷新绑定原会话，退出、跨标签页换号或首次要求改密时取消待决确认；共用列表与导出忽略换号或页面卸载后的迟到结果（#42）。
- 跨标签页更换账号时先卸载旧业务页，完成新身份和菜单校验后再挂载；即使落点路径相同也重建页面，避免旧删除或导出的忙碌状态留在新会话。

## 升级说明与限制

- 前后端统一升级到 v0.12.0 并配套部署；首次改密新增的响应标记和独立流程、生成配置的新接口都要求匹配的前端。没有新增依赖或必填环境变量，xdb 地名库与 2FA 仍按既有可选配置规则启用。
- 升级前备份 SQLite 数据库。正常启动执行已嵌入二进制的 `0012_password_change_required.sql` 与 `0013_generator_sync.sql`，无需另行复制迁移目录；`--check-config` 不执行迁移，不能替代实际升级验证。保留历史迁移文件与校验记录，不修改已发布迁移。
- 迁移 `0012` 为历史账号增加默认关闭的改密标记，不修改已有口令，不自动要求历史或种子账号改密。新增用户与重置密码的 `passwordChangeRequired` 省略或为 `false` 时保留原行为；普通编辑不能清除要求。已启用 2FA 的账号仍须先通过第二因素，待改密会话只可读取本人信息、改密和退出，超管也不能绕过。
- 本人改密核对旧密码与认证版本，密码、改密标记及安全版本在同一事务提交；成功后全部旧会话失效并要求重新登录。事务提交后 Redis 清理失败不会回滚已完成的密码修改，残留令牌由版本比较拒绝。
- 迁移 `0013` 为表配置增加内部版本，为列配置保存完整 SQL 声明类型；旧记录使用原 `jdbc_type` 回填，保留历史配置基线。旧 `varchar` 配置首次对照 `VARCHAR(64)` 时会显示类型变化，这是历史配置缺少长度信息的预期差异，确认后不再重复出现；仅类型大小写差异不算变化。
- 结构同步只更新生成配置，保留表身份、表级自定义设置及未变列；列重命名按删除旧列和新增新列处理。实际变化后设为待人工确认，`synced` 不是实时数据库同步状态；无差异不写入。预览后仍可同步的结构或配置变化返回 409，须重新预览；目标配置或业务表不存在、主键不受支持时返回 400，该同步请求不写入配置。同步不执行业务表 DDL、不修改业务行、不覆盖已下载代码。
- 「移除配置」永久删除所选表的生成元数据及全部列配置，自定义设置不会通过重新导入恢复；业务表、数据及已生成文件保留。业务表仍存在且满足导入限制时可以重导，得到新的配置 ID 和默认设置，旧 ID 的迟到请求不能影响新配置。需要保留设置并跟随结构变化时使用「同步结构」。同步或移除完成后的审计失败不会回滚已经提交的业务结果。
- 代码生成仍仅支持 SQLite 单列 `INTEGER` 行号主键，不支持文本、复合、无主键或非行号主键。预览与 ZIP 使用同一份持久配置；产物仍为 axum + sea-orm 分层骨架，需补全业务规则、写操作及接入装配，未实现处保留 `todo!`，不承诺直接投产。
- `--check-config` 在实际服务使用的工作目录和环境中运行，退出 0 仅表示限定检查通过；失败以非 0 退出并给出不含敏感原值的诊断。检查复用环境 / `.env`、配置约束、监听地址格式、日志过滤 / 时区、SQLite / Redis 驱动配置解析及已配置 xdb 的只读加载规则；production 仍要求 release 构建。原有 `.env` 加载错误忽略语义不变，不能据此认定整份 `.env` 语法已完整验证；xdb 检查也不是整库内容扫描。
- 预检不连接 SQLite / Redis、不迁移或播种、不初始化文件日志、不创建数据库或日志目录、不监听 HTTP。通过不证明依赖可达、目录可写、端口可用、迁移兼容或服务就绪；已配置 xdb 不可读、加载失败或协议不匹配会失败。部署时继续按 `docs/DEPLOYMENT.md` 完成正常启动与健康 / 就绪验证。

- 浏览器验收使用本地 Chrome 与隔离 SQLite / Redis；未验证 Firefox / Safari、实体手机或生产部署。上游 `proc-macro-error2 2.0.1` 的 Rust future-incompatibility 提示仍存在。
