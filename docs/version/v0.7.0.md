# v0.7.0

一次以「修复已知缺陷」为主的版本：后端补上权限越权、部门移动、种子数据、状态取值、
菜单授权、Redis 连接串、分页上限、CSV 导出、改密会话、日志脱敏、锁定计数、2FA 计数、
验证码原子性与生成器导入等 15 处问题；前端统一分页上限，并修掉批量操作与看板搜索的状态不一致。
对外可见的变化集中在若干新的 4xx 文案与一处配置行为收紧，接口契约与权限码不变。

## 后端

- **授予超级管理员角色必须由超管本人操作**：此前只要请求者具备 `system:user:edit` 权限即可给任意账号
  （含自己）授予 `super_admin`，等同于把「分配角色」变成提权入口。现在新增 / 编辑用户的角色集合里
  出现超级管理员角色时，操作者必须本身是超级管理员，否则返回 400。
- **移动部门时重算整棵子树的祖先链并拒绝成环**：此前只更新目标部门自己的 `ancestors`，
  其下级仍指向旧的祖先路径，部门树与数据范围（`DEPT_AND_CHILD`）随之错乱。现在在同一个写事务里
  重建全部后代的祖先链；把部门挂到自己或自己的下级下面返回 400（「上级部门不能是部门自身」/
  「上级部门不能是部门自身的下级」），层级出现环时报「部门层级存在环，无法移动」。
- **种子数据不再补发管理员已撤销的角色与岗位**：此前每次启动都会用 `INSERT OR IGNORE` 补齐演示关联，
  运维手工撤销的演示角色 / 岗位会在下次重启后自动回来。现在只有该账号在这张关联表里**一条记录都没有**时
  才填演示数据（保留「克隆即可运行」），已有任何记录的账号保持原样。
- **编辑用户接口拒绝 0 / 1 以外的状态值**：`PUT /api/v1/system/users/{id}` 的 `status` 此前只有
  「内置管理员不允许停用」一道保护，传 `2`、`-1` 之类的值会把账号写成既非正常也非停用。
  现按 `/status` 端点同口径校验，非法值返回 400「用户状态只能为正常或停用」。
- **角色菜单授权拒绝不存在的菜单**：创建 / 更新角色的 `menuIds` 此前直接写进 `sys_role_menu`，
  不校验菜单是否存在，会留下悬空授权行。现与已有的部门校验一致，非法值返回 400「菜单不存在或已删除」。
- **Redis 连接串对口令做 userinfo 转义**：`REDIS_PASSWORD` 此前直接拼进连接串，含 `#` 会被当成 fragment
  起点、含 `/` 会被当成路径分隔，`redis` 客户端解析出的 host 与 db 都会错位。现按 URL 规则转义
  （新增依赖 `url`，已在依赖树中，用于 `form_urlencoded`）。
- **分页超过上限显式拒绝**：`pageSize` 此前静默截断到 100，客户端拿到半页却以为是整页，分页总数与
  实际行数对不上。现在超过 100 返回 400「每页条数不能超过100」；缺省与 `0` 仍取默认值。
- **导出 CSV 时中和公式前缀**：用户昵称、请求参数等由用户控制的字段，以 `=` `+` `-` `@` 或制表符 / 回车
  开头时，导出后会被表格软件当成公式执行（双击打开即可触发外链与命令）。这类单元格现在前置单引号保持文本，
  普通文案不受影响。
- **用户改密后递增会话版本**：`PUT /api/v1/auth/password` 此前只撤销 Redis 里的会话，令牌索引缺失或
  Redis 故障时旧 JWT 仍能通过验签。现与管理员重置口令一致，在写事务里递增 `auth_version`，
  Redis 清理移到事务外且失败只告警。
- **未匹配路由的日志不再记录 query 串**：404 的 `not_found` 此前把完整 URI 写进日志，未匹配请求同样可能
  带着令牌、验证码等参数。现在只记 path。
- **锁定窗口过期后重置口令失败计数**：锁定到期后计数仍停在阈值，下一次失败直接越过阈值并立刻再锁一遍，
  用户相当于每次只错一次就被锁 5 分钟。现在窗口过期时先把计数清零再累加。
- **2FA 失败计数与口令阶段分离**：两个阶段此前共用 `sys_user_security` 的 `failures` / `blocked_until`，
  验完口令就把计数清零，而 6 位动态码每次口令正确即可再试，等同 2FA 无限重试。现在新增
  `factor_failures` / `factor_blocked_until` 两列（迁移 `0010_factor_attempts.sql`）独立计数；
  口令阶段也不再受 2FA 锁定影响，锁定后仍能正常拿到新 challenge。
- **Redis 验证码改用 `GETDEL` 原子取用**：此前 `GET` 再 `DEL` 两条命令，并发请求同一个 uuid 可能各取到
  一次明文，验证码的一次性形同虚设。改用 Redis 6.2+ 的 `GETDEL`。
- **生成器导入先确认底层表仍存在**：导入先查生成配置，命中就直接复用 id、不再复核 `sqlite_master`，
  底层表被删掉后旧配置依旧指向它，导入反而报成功。现在先校验表存在，缺失返回
  400「数据库表不存在：<表名>」。
- **下载文件名去掉永远不会命中的后缀裁剪**：`className` 由表名转驼峰得到，不可能以 `Controller` 结尾，
  `strip_suffix` 恒走兜底分支且注释与行为不符，已删除该分支与随之失效的常量。

## 前端

- **分页上限统一引用 `MAX_PAGE_SIZE`**：`Configs.vue`（500）、`Dict.vue`（200）、`Posts.vue`（200）
  三处调用超过后端上限，`Users.vue` 另有一份 `BOARD_LIMIT` 副本。现在统一从 `src/api/system.ts` 导入，
  与后端 100 条上限对齐，避免自己撞上新的 400。
- **批量操作中途失败时仍刷新列表**：用户 / 岗位 / 操作日志 / 登录日志的批量删除与批量改状态用 `Promise.all`，
  一条失败就跳进 `catch`，而前面已成功的条目没回源，界面停在一半改完的状态。刷新移到 `finally`。
- **用户看板丢弃乱序返回的旧请求**：看板搜索有 320ms 防抖，慢网下先后两个请求可能乱序返回，
  后到的旧结果会覆盖新关键词的结果。`loadBoard` 加请求序号，只接受最后一次发出的响应。
