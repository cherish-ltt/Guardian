# v0.4.1

本次发布让后端产物明确区分 glibc 与 musl 运行时，共四个下载包，并简化了包内结构。

## 后端

- **产物按 libc 区分**：此前包名只写架构，下载者无法判断能否在 Alpine 等 musl 发行版上运行。
  现在按「架构 × libc」提供四个包：
  `x86_64-linux-gnu`、`aarch64-linux-gnu`、`x86_64-linux-musl`、`aarch64-linux-musl`。
  gnu 包动态链接 glibc；musl 包静态链接，可在任意 Linux 发行版上直接运行。
- **产物结构简化**：压缩包内二进制由 `target/release/guardian-backend` 改为根位置的
  `guardian-backend`，与 `.env-example` 并列，解压即可部署。打包步骤额外打印包内清单，
  发布日志里可直接核对结构。
- **产物不再附带 `migrations/`**：迁移 SQL 由 `sqlx::migrate!` 在编译期嵌入二进制，运行时不再读
  磁盘上的迁移目录，包里保留它只是冗余副本。
- **构建方式**：gnu 目标在原生 runner 上编译；`x86_64-musl` 用 apt 的 `musl-tools`；
  `aarch64-musl` 用 musl.cc 的预编译工具链交叉编译。不能用 `aarch64-linux-gnu-gcc` 充当 musl
  链接器——那是 glibc 工具链，会因缺少 `stat64` 等符号链接失败。

## 前端

- 无。版本号随本次发布同步递增到 `0.4.1`，代码无改动。
