# v0.3.0

本次发布把登录验证码开关做成真正生效的功能，并统一了前后端版本号。

## 后端

- **登录验证码开关**：`sys.account.captchaEnabled` 参数重新种入 `sys_config`（`builtin = 0`，
  可在「参数配置」页直接开关）。关闭时 `GET /api/v1/auth/captcha` 返回 `enabled = false`
  且不再生成验证码、不写 Redis，`POST /api/v1/auth/login` 跳过验证码校验。
  参数缺失时按开启处理，不会因为读不到参数而放宽登录。
- **`CaptchaChallenge` 增加 `enabled` 字段**：登录页据此决定是否渲染验证码输入框。
- **契约测试**：新增 `captcha_is_enabled_by_default` 与 `disabled_captcha_skips_verification`，
  锁定开关的两种状态（后者还断言关闭后口令仍被校验）；`config_flow_and_export`
  的参数总数断言改为 3 条。
- **文档**：`backend/docs/ADMIN.md` 的接口表与「与 Spring 版的差异」同步改写。

## 前端

- **登录页按开关渲染**：`/auth/captcha` 返回 `enabled = false` 时隐藏验证码输入框、
  取消非空校验，登录请求体不再带 `captcha` / `captchaUuid` 字段。
- **`LoginRequest` 类型**：`captcha` 与 `captchaUuid` 改为可选，与后端 `LoginCommand`
  的 `Option<String>` 对齐。
- **单元测试**：新增用例断言关闭态下 `captcha()` 的返回值与登录请求体形状。
